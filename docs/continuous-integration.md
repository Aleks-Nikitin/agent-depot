# Continuous integration

`.github/workflows/ci.yml` runs on pull requests targeting `main` and pushes to `main`. It uses Node 24, a disposable PostgreSQL 16 service, read-only repository permissions, and a 20-minute timeout. Superseded runs for the same workflow/ref are cancelled. The setup follows GitHub's [Node workflow](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs) and [PostgreSQL service](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers) conventions.

The job installs locked dependencies, generates Prisma, deploys additive migrations, installs graph/queue vendor schemas and prepares the restricted evaluation database on that same PostgreSQL instance. It creates an ignored `.env` only for disposable evaluation credentials generated by the local setup script. It then runs type checking, lint, all unit tests, the full integration suite and the standard Turbopack production build. There is no deployment, artifact upload, hosted database access, secret import or paid-provider credential in the workflow.

The workflow supplies fixture model/pricing configuration with provider/search/tracing keys empty. Integration tests use explicit deterministic drivers or mocked provider responses. `TEST_OFFLINE=1` installs a fetch guard before integration-test imports: unexpected external requests fail before network I/O, and permitted loopback requests do not automatically follow redirects. Provider tests can replace fetch with their explicit response mocks. The guard does not replace model behavior, weaken runtime assertions or change production code. `TEST_OFFLINE` governs tests; build-time public font downloads are separate from provider calls.

The full integration lane covers the current 202 receipt transport, owned execution, approval idempotency, browser disconnection after durable claims, shared budgets, narrow policies, isolated outcomes and promotion evidence. Synthetic test tools receive explicit parent-policy fixture grants; the production allowlist is not widened to make tests pass.

## Local verification

Use a disposable loopback PostgreSQL database, install the graph/worker schemas, and configure the restricted evaluation database before running:

```sh
npm run typecheck
npm run lint
npm test
TEST_OFFLINE=1 DATABASE_TARGET=local npm run test:integration
npm run build
```

Workflow YAML parsed successfully. Local checks passed type checking, lint, 121 unit tests and 89 integration tests with offline mode enabled. The production build was attempted but remains blocked by the local execution environment denying Turbopack's CSS worker a port bind. No bundler replacement or suppressed build step is used. A successful GitHub-hosted build/run is not claimed: the workflow has not been pushed or dispatched. Review and integration remain separate from local verification.
